# Shared usage index: implementation and proof

This document describes the implemented change, not a second PRD. It supersedes the old assistant-only synchronous full-scan plan; README.md documents the user-facing behavior.

## Shipped path

- `src/index.ts` retains `/usage`, `models`, `days`, `months`, `sessions`, `projects`, `refresh`, `help` and `/usage footer` settings. Explicit reports request bounded reconciliation (2.5 seconds); incomplete/stale/loading output is labeled. Refresh reconciles changed files; it does not force an unchanged-content reread.
- `src/usage-adapter.ts` receives Pi `turn_end` persisted entry IDs and immediately renders a local usage overlay. No scan or database operation is awaited at the turn boundary. A generation-scoped UI status sink prevents an old session's background result updating its replacement. Every 50 seconds an idle process reconciles metadata and updates its footer from shared data.
- `src/usage-index.ts` moves reconciliation and SQLite I/O into a worker; `src/usage-index-core.ts` keeps source-file checkpoints, provenance, usage rows and canonical deduplicated projection in `<agent-dir>/token-usage-index-v1.sqlite`. The JSONL tree at `<agent-dir>/sessions/` remains authoritative. Rebuild by stopping Pi, removing the index plus `-wal`/`-shm` files and restarting, retaining JSONL. Unchanged session bodies are not reopened on routine sweeps, including deletion-only sweeps. A failed listing/parse does not authorize deletions; concurrent stale imports and older deletion walks cannot replace newer committed sources.
- Supported recorded usage: assistant, tool-result, standalone usage, compaction and branch-summary; copied charges count once, independent short-ID collisions remain distinct, child cwd drives project assignment, evidenced branch model attributes compaction or it remains `unattributed`. Day/month rollups use local calendar dates; top session rows are additive canonical charges, not overlapping Pi session totals.

## Proof and boundary

`npm test` exercises parser/store traces, copy/delete/rewrite/truncate, failures/recovery, concurrent stale-walk/import races, command dispatch and lifecycle. `npm run test:e2e` runs Python 3 stdlib PTY against **real interactive Pi 0.87.1**, explicitly loading this source extension and a local scripted faux provider. A test-only gate (`PI_TOKEN_USAGE_TEST_GATE`, a path present only in test processes) blocks historical worker reconciliation while a turn must settle and its own usage appears. The scenario drives footer off/on, a warned bounded `/usage` timeout, a real `/new` session while the old import is pending, and recovery. It starts a second Pi on the same temporary agent tree, observes passive child usage within 60 seconds, checks copy/deletion/rewrite from user-visible reports, then restarts a Pi process against the retained index. A test-only body-read trace proves the restart did not reopen unchanged transcripts. A mixed retained history with nonzero costs then exercises tool-result, standalone, compaction and branch-summary charges through real `/usage models`, day/month and additive session rows, plus footer settings. It uses no live model or tmux. Terminal captures and the temporary index are printed by the runner; no test failure is skipped.

Scope: only the current agent session tree, not archive roots, arbitrary `--session-dir`, ephemeral sessions without JSONL, provider invoice reconciliation or Pi core. The personal machine's local proof is not a live axon-work-computer test. Before work-host deployment, verify Pi `^0.87.1` and Node's `node:sqlite`/worker support there, then smoke-test a real work-host turn, `/usage`, idle child catch-up and footer setting against that host's retained tree. No installation, deployment or chezmoi change is part of this worktree task.
